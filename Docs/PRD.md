# 게임 MVP — 뉴게임에서 엔딩까지 (S0~S6)

> 출처: `brief.md` → `design.md`(설계 결정서) → `minimal_구조_mvp.md`(엔진/콘텐츠 분리).
> 이 문서는 위 세 문서에서 **합의된 것만** 옮긴다. 새 결정은 없다.
> 범위: **S0~S6**. S7(콘텐츠 채우기·CG 24매·사운드·번역·폴리시·스토어)은 범위 밖.

## 문제

1인 개발 + AI 바이브코딩으로 만드는 첫 상업 게임이고, 가장 큰 리스크는 **완성하지 못하는 것**이다. 시그니처 전투(검기 발도술)가 재미없으면 나머지 콘텐츠가 아무리 좋아도 게임이 성립하지 않는데, 그 전제는 아직 손으로 검증된 적이 없다. 동시에 세계관·수치·텍스트가 코드에 박히면 나중에 콘텐츠를 갈아끼우거나 스코프를 자를 때 비용이 폭발한다.

## 해결책

**"규칙만 아는 엔진" + "전부 텍스트인 콘텐츠 팩"** 두 겹으로 만들고, 그 위에 7개 수직 슬라이스를 쌓는다. 각 슬라이스 종료 시 항상 플레이 가능하며, **S1(손맛)** 과 **S3(루프 한 바퀴)** 두 곳에 중단 권한이 있는 검증 게이트를 둔다. 침식 게이지 하나가 타이머·실패비용·리스크·드롭보정·연출·오디오를 전부 담당하고, 관계 수치 하나가 CG·엔딩분기·판매 트레이드오프를 전부 담당한다 — **축을 줄이고 서로 곱한다.**

## 사용자 스토리

### S0 — 콘텐츠 인프라 (3~5일)
- [ ] 엔진 개발자로서 콘텐츠 팩을 통째로 비우고 실행하면 크래시 없이 "콘텐츠 없음" 화면 + 검증 리포트를 얻는다
  - 완료 조건: **빈 팩 부팅 테스트**가 CI에서 통과. `Game.Domain.asmdef`에서 UnityEngine 참조를 뺀 채 컴파일된다
- [ ] 콘텐츠 작업자로서 Unity 없이 콘솔에서 `dotnet run --project Tools/ContentValidator -- ./content`를 돌리면 내 팩의 오류를 전부 한 번에 받는다
  - 완료 조건: 검증 10항목이 첫 에러에서 멈추지 않고 **모아서 한 번에** 출력. 파일명·줄 번호 포함

### S1 — 발도술 (2주, 🚩 게이트 1)
- [ ] 플레이어로서 우클릭을 홀드해 파워바를 채우고 릴리즈하면 타이밍에 따라 취소 / 스윗스팟 / 늦음 3구간으로 갈리는 결과를 얻는다
  - 완료 조건: `ChargeLogic` EditMode 테스트 통과(경계값·자동발사 포함). 스윗스팟 구간이 파워바에 항상 표시된다
- [ ] 플레이어로서 스윗스팟에 성공하면 검기가 적을 관통해 `maxRange`까지 간 뒤 U턴해 나를 추적하며 돌아와 **왕복 2히트**(정면타 + 배후타)를 낸다
  - 완료 조건: `SwordWaveLogic` 상태 전이(Idle→Charging→Flying→Returning→Idle) + 타임아웃 안전망 테스트 통과
- [ ] 플레이어로서 성공과 실패의 피드백이 확연히 다르게 느껴진다
  - 완료 조건: 효과음 5종 + 히트스톱(0.05~0.12s) + 스크린 셰이크가 붙어 있고, 전부 config 값을 구독한다
- [ ] 개발자로서 F1 튜닝 패널에서 숫자를 바꿔 즉시 손맛을 조정하고, 계측 로그로 성공률을 확인한다
  - 완료 조건: 계측 4항목(스윗스팟/늦음/취소 비율, 평균 차지 시간, 검기 적중률, **왕복 2히트 달성률**) 출력. 패널 편집 결과가 JSON에 되쓰기된다
- [x] **🚩 게이트 1**: ① 튜닝을 멈춘 상태로 연속 10분 이상 계속 베고 있는가 ② 숙련 후 스윗스팟 성공률 60~75%에 안착하는가(로그로) ③ 설명 없이 5분 플레이한 3명 중 2명 이상이 자발적으로 "한 번 더"를 말하는가

### S2 — 1층 다이브 (2~3주)
- [ ] 플레이어로서 산(1층)에 진입하면 침식 게이지가 초당 0.20씩 줄어들고, 적에게 접촉하면 8~12를 잃는다
  - 완료 조건: `ErosionLogic` 테스트 통과(시간·피격 감소, 정화 회복과 상한 100, 구간 판정, 0 도달 처리)
- [ ] 플레이어로서 정화 노드를 밟으면 즉시 게이지가 회복되지만, 그만큼 드롭 등급 상승 확률을 잃는다
  - 완료 조건: 버튼·UI·인벤토리 슬롯을 쓰지 않는다. 밟는 순간이 곧 소비
- [ ] 플레이어로서 게이지가 낮을수록 화면·오디오가 변하고 금기 재료의 드롭 등급이 올라간다
  - 완료 조건: `OnBandChanged` 이벤트를 Presentation이 구독. **조작 방해(입력 지연·조준 흔들림·화면 반전)는 0개**
- [ ] 플레이어로서 적을 베면 금기 재료가, 채집 노드를 3초 홀드하면 일반 재료가 배낭에 들어간다
  - 완료 조건: `BackpackLogic` 테스트 통과(용량 초과, 스택, 50% 상실 계산). 가득 차면 획득 실패 + 안내, 자동 폐기 없음
- [ ] 플레이어로서 밧줄에 도달하면 전리품을 전부 지키고, 게이지가 0이 되면 강제 귀환하며 배낭의 50%를 잃는다
  - 완료 조건: `DiveSession` 전체 시뮬레이션 테스트 통과. 결과 화면에 도달 층·귀환 방식·전리품·**상실분**·예상 판매가가 보인다

### S3 — 마을·약방·경제 (2~3주, 🚩 게이트 2)
- [ ] 플레이어로서 귀환하면 가마솥이 완성되어 있고, 재료를 다시 투입한 뒤 다음 다이브를 나간다
  - 완료 조건: **실시간 타이머 없음.** 진행 단위 = 다이브 횟수. `CauldronLogic`/`RecipeLogic` 테스트 통과
- [ ] 플레이어로서 가공품을 팔거나 원재료를 30% 가격에 직판해 골드를 얻는다
  - 완료 조건: `PricingLogic` 테스트 통과(품질 점수 → 3단계 티어 → 배수 1.0/1.5/2.2, 직판 30%)
- [ ] 플레이어로서 투입 전에 예상 품질을 미리 볼 수 있어 재료를 저울질한다
  - 완료 조건: 약방 화면 하나에 가공/판매/사용/설비가 **탭으로 통합**되어 있다
- [ ] 플레이어로서 마을 귀환 정산이 끝나면 자동 저장되고, 다시 켰을 때 같은 상태로 이어진다
  - 완료 조건: `SaveComposer` 테스트 통과(직렬화 왕복, **미지 ID 무시**, **없는 필드 기본값**). 던전 내부 저장 없음, 슬롯 1 + 백업 1
- [ ] 개발자로서 22사이클 경제 시뮬레이터를 돌려 골드·업그레이드·해금 곡선을 CSV로 얻는다
  - 완료 조건: `dotnet run --project Tools/EconomySim -- ./content --cycles 22`가 Unity 없이 실행된다
- [x] **🚩 게이트 2**: 연속 5바퀴를 돌고 싶어지는가. 3바퀴째에 지루하면 보상 간격·배낭 크기·가격 곡선을 지금 손본다

### S4 — 성장과 깊이 (2주)
- [ ] 플레이어로서 작업대에서 배낭·침식 저항·무기 강화를, 약방에서 가마솥 슬롯·정제 설비를 산다
  - 완료 조건: `UpgradeLogic` + `UpgradeEffectRegistry`(효과 키 6개) 테스트 통과. 5축 × 3단계 = 15단계
- [ ] 플레이어로서 2층으로 내려가거나, 도달했던 층부터 다이브를 시작한다
  - 완료 조건: 시작 침식이 층별로 다르게 적용(1층 100 / 2층 70)
- [ ] **구조 게이트**: 적 2종 추가가 `enemies.json`에 항목 두 개를 쓰는 것으로 끝난다
  - 완료 조건: **C# 파일 수정 0줄.** 한 줄이라도 건드렸다면 여기서 멈추고 원인을 고친다

### S5 — 관계와 CG (1~2주)
- [ ] 플레이어로서 레시피를 해금하거나 약을 과부에게 사용하면 관계 수치가 오르고, 임계값을 넘으면 CG가 열린다
  - 완료 조건: `AffinityLogic` 테스트 통과. 임계값 다중 돌파 시 **순차 재생**
- [ ] 플레이어로서 마을에 돌아오면 조건을 만족한 약방 대화가 초상화 + 텍스트로 재생된다
  - 완료 조건: `TriggerEvaluator` 조건 9종 × 효과 9종. **조건 배열은 AND만, 조건식 문자열 파서 0줄**
- [ ] 플레이어로서 CG 갤러리에서 해금분을 다시 보고, **미해금 칸도 잠긴 상태로** 확인한다
  - 완료 조건: placeholder 8종 해금 → 갤러리 동작. 스토리 사건 하나 추가에 C# 수정 0줄

### S6 — 엔딩 (2~3주)
- [ ] 플레이어로서 3층 최심부에서만 나오는 재료를 가져와 최종 레시피를 완성하면 엔딩을 본다
  - 완료 조건: 관계 수치 기준 엔딩 2~3종 분기(텍스트 + CG 차이만). 무조건 성립하는 엔딩이 1개 존재
- [ ] 플레이어로서 타이틀에서 새 게임·이어하기·옵션·종료를 고른다
  - 완료 조건: 옵션에 볼륨 3종 / 언어 / 창모드·해상도 / 조작 안내
- [ ] **완료 정의**: **뉴게임 → 엔딩까지 중단 없이 클리어 가능**

## 모듈 맵

두 겹 구조: `Game.Domain`(UnityEngine 참조 0) ← 주입 ← `StreamingAssets/content/`(JSON + CSV).
`Game.Unity`는 "무엇이 닿았는가"와 그리기만 담당한다.

| 모듈 | 상태 | 인터페이스 / 책임 |
|---|---|---|
| `Content/` (ContentLoader·ContentValidator·ContentDatabase) | 신규(deep) | `Load(path) → ValidationReport`, `db[id] → POCO`. 뒤에 JSON 파싱·검증 10항목·참조 무결성·ParamSchema 검사가 전부 숨는다. 로드 후 **읽기 전용** |
| `Combat/` (`IWeaponBehavior` + `ChargeWaveBehavior` + `ChargeLogic`·`SwordWaveLogic`) | 신규(deep) | 좁은 인터페이스: `입력 + Tick → 히트 이벤트 + 상태`. 무기별 파라미터 지식이 그 behavior 클래스 **하나에만** 산다. **초기 구현은 `charge_wave` 1개** |
| `Enemy/` (`IEnemyBehavior` + Chaser·Wanderer·Ranged) | 신규 | 상태 2개(배회/추적)만. 접촉 데미지는 AI가 아니라 물리 |
| `Erosion/ErosionLogic` | 신규(deep) | 시간·피격 감소, 정화 회복, 구간 판정, 0 도달 처리. 구간은 **배열**이라 3구간이 5구간이 되어도 코드 불변 |
| `Inventory/BackpackLogic` | 신규 | 슬롯·스택·가득참·50% 상실 계산 |
| `Dive/DiveSession` | 신규(조정자) | `Start(floorId, loadout)` / `Tick(dt, playerPos, hits)` / `RequestExtract()` / `GetState()` + 이벤트 3종. **경계 조건 판정이 전부 여기서 끝난다.** 300줄 초과 = 신 객체 신호 |
| `Alchemy/` (CauldronLogic·RecipeLogic) | 신규 | 슬롯 점유, 다이브 횟수 기반 진행, 레시피 매칭·재료 부족 |
| `Economy/PricingLogic` | 신규 | 품질 점수 → 티어 → 판매가, 직판 비율 |
| `Progression/` (UpgradeLogic·AffinityLogic·UpgradeEffectRegistry) | 신규 | 효과 키 6개 × op(`set`/`add`/`mul`). 축·단계 수는 데이터 |
| `Narrative/` (StoryDirector·TriggerEvaluator·FlagStore) | 신규(deep) | 조건 9종·효과 9종을 **하나의 평가기**로. 스토리·엔딩·레시피 해금이 같은 부품을 재사용 |
| `Cycle/CycleSession` | 신규(조정자) | 정산 → 가공 완료 → 판매 → 업그레이드 → 관계 → 이벤트 판정 → 세이브 **순서를 소유**. 22사이클 시뮬레이터가 도는 대상 |
| `Persistence/SaveComposer` | 신규 | 각 모듈의 `ToState()`/`FromState()`를 **합쳐서 직렬화만.** 해석하지 않는다 |
| `Rng/SeededRng` | 신규 | seed 주입. Domain 내 `UnityEngine.Random`/`Time`/`DateTime.Now` 금지 |
| `Game.Unity/Boot` (GameBootstrap + 레지스트리 5종) | 신규 | 등록은 여기 **한 곳**. 새 행동 = 클래스 하나 + 등록 한 줄, 기존 코드 수정 0 |
| `Game.Unity/Presentation` | 신규(얇게) | 화면 7개. **데이터를 그리기만.** 화면이 "레시피가 3개다"를 알면 안 된다 |
| `Game.Unity/Tuning/TuningPanel` | 신규 | F1, IMGUI 30줄. config POCO 편집 + [저장]이 JSON에 되쓰기. **못생겨도 된다** |
| `Tools/ContentValidator` (CLI) | 신규 | Unity 없이 콘솔 실행. 새 작업자가 Unity 설치 없이 자기 팩 검증 |
| `Tools/EconomySim` | 신규 | N사이클 자동 플레이 → 곡선 CSV |

## 구현 결정

### 절대 규칙 3개 (CI가 강제)
1. **코드에 문자열 리터럴 금지** — 콘텐츠 ID도, 표시 텍스트도. 후자는 로케일 키로
2. **코드에 튜닝 숫자 금지** — 예외는 0, 1, 배열 인덱스
3. **콘텐츠 enum 금지** — 문자열 ID + 레지스트리로
> `Game.Domain` 전체에 정규식 grep 두 개를 돌려 허용 목록 밖이면 빌드 실패. **규율이 아니라 도구가 지킨다.**

### 전투
- 차지 중 이동 **가능, 속도 50~60%**. 감속이 곧 차지의 비용
- 조준은 마우스 커서 방향, **회전 속도 제한 없음**. 게임패드는 범위 밖
- 스윗스팟 **항상 시각 표시**. 관통 **무제한**(S2 적 밀도 튜닝 중 재검토)
- 목표 성공률 **숙련 후 60~75%**
- 비행 중 재조준 불가. 귀환은 플레이어 추적이므로 크게 움직이면 배후타를 놓친다
- 타격감 3종(효과음 5 / 히트스톱 0.05~0.12s / 셰이크: 정면타 약·배후타 강)은 **S1 필수**. **BGM은 S1에 넣지 않는다** — 분위기가 판정을 오염시킨다

### 침식 게이지 (단일 자원)
| 항목 | 값 |
|---|---|
| 시작값 | 100 (1층) / 70 (2층) / 40 (3층) |
| 시간 감소 | 1층 0.20 / 2층 0.25 / 3층 0.35 (초당) |
| 피격 감소 | −8~12 |
| 회복 | **정화 노드만.** +15~20, 상한 100 |
| 층 이동 | 이어진다. 리셋 없다 |
| 0 도달 | **사망 아님.** 강제 귀환 + 배낭 50% 상실 |

- 층당 통과 비용이 약 30이 되도록 잡았고, 그래서 시작 침식 100/70/40이 **"무피격 숙련자의 잔량"** 그 자체다 → 직행과 연속 하강이 게이지 면에서 동등하다. 갈리는 것은 **배낭**
- 구간: 100~60 평정 / 60~30 감각 예민(드롭 등급 +1 확률) / 30~0 침식 심화(확률 대폭 증가). **낮을수록 위험하고 더 좋은 것이 나온다**
- **조작 방해 금지.** 표현은 시청각으로만
- 등급 상승 확률은 `erosion.json`이 소유하고 드롭 목록은 `droptables.json`이 소유한다 — **규칙을 두 곳에 두지 않는다**

### 층·맵·귀환
- 다이브 1회 = 1층(산, 지상) → 2층(광산 상부) → 3층(최심부) 연속 하강. **산은 별도 씬이 아니라 1층 그 자체**
- 층당 체류 2~3분 / 다이브 6~9분 / 사이클 8~12분
- **고정 레이아웃 + 스폰 테이블 랜덤.** 절차 생성·미니맵 없음
- 밧줄: 층당 후보 4~5 중 **2개 활성**. **어느 지점에서든 가장 가까운 활성 밧줄까지 45초 이내**. 화면 밖이면 가장자리 방향 화살표(필수)
- 하강 지점과 밧줄은 다른 방. 순서는 밧줄 → 하강 지점, 단 하강 지점 바로 앞에 밧줄 하나 더
- 1층 귀환 연출만 등불 이정표(`extractStyle`), 시스템은 하나
- 실패 후 **재진입 마찰 없음**

### 적
- 상태 2개(배회/추적)만. 피격 반응·회피·패턴 공격·협동 없음
- 추적형 속도는 플레이어보다 약간 느리게
- 층별 변형은 **스탯과 색(tint)만.** 겉보기 9종, 구현 3종, 신규 코드 0줄
- 밀도(적/재료노드/정화노드): 1층 5~7 / 4~5 / 2 · 2층 7~9 / 4~5 / 1~2 · 3층 9~12 / 3~4 / **0~1**

### 재료·인벤토리
- 획득 경로 가치 비율 **적 처치(금기 재료) 70 : 채집 노드(일반 재료) 30**. 채집은 3초 홀드
- 슬롯 8 → 11 → 14 → 17. 스택 일반 5 / **금기 3**
- 가득 참 = 획득 실패 + 안내, 자동 폐기 없음. 재료 위 재상호작용 시 원클릭 교체
- **다이브 중 일시정지 없음.** 마을 보관은 무제한

### 약방·경제
- 가공 시간 단위 = **다이브 횟수**(실시간 타이머 아님). 가마솥 슬롯 1 → 2 → 3
- 원재료 직판 가능, 가공품의 **30%**
- 품질 점수 = 투입 재료 평균 등급(1~3) + 정제 설비 보너스(0 / +0.3 / +0.6 / +1.0) → 3단계, 배수 **1.0 / 1.5 / 2.2**
- **최상급(2.2)은 설비만으로 도달 불가** — 설비는 하한을, 깊이는 상한을 올린다
- **조합 미니게임 없음.** 손맛은 발도술 하나에만
- 투입 전 **예상 품질 미리보기**

### 진행·보상
- 업그레이드 5축 × 3단계 = **15단계**: 배낭(수확량) / 침식 저항 −15%씩(도달 깊이) / 무기 강화 공격력 +40%·검기 크기 +15%(처치 속도) / 가마솥 슬롯(처리량) / 정제 설비(품질 하한)
- **무기 강화는 스윗스팟 창을 넓히지 않는다** — 실력 곡선과 장비 곡선을 섞지 않는다
- 관계 수치는 **단일 스칼라**. 오르는 경로는 둘: 레시피 해금(자동) / 약을 과부에게 사용(골드를 포기하고 가속)
- CG 8종 × 변형 3단계 = 24매. 해금은 `{ cgId, requiredAffinity }` **한 줄**. 첫 장은 2~3사이클(약 25분). **S6까지는 회색 사각형 placeholder**
- 엔딩 = 최종 레시피 완성. 필요 재료 하나는 **3층에서만** 나오고, 최심부 도달에는 침식 저항이 필요하다 → 파밍 루프가 구조적으로 강제된다. 보스전 없음

### 마을·UI
- 마을 씬 하나, 상호작용 3개: 심야 약방(과부, **유일한 NPC**) / 작업대(오브젝트) / 산길 입구(오브젝트)
- 화면 7개: 타이틀 · 다이브 HUD · 다이브 결과 · 약방(탭 통합) · 작업대 · CG 갤러리 · 옵션
- **각 화면은 한 가지 일만 한다**
- 결과 화면에서 **상실분을 흐리게 넘기지 말 것**
- **HUD에서 "침식"을 게이지 이름으로 쓰지 않는다** — 채워진 양이 곧 남은 여유로 보이게. "침식"은 구간 상태 표시에만. 내부 이름은 `ErosionLogic` 유지
- 파워바·스윗스팟 표시는 UI가 아니라 **게임플레이 부품**

### 온보딩 (튜토리얼 씬을 따로 만들지 않는다)
- 1단(첫 3분): 0:00 도입 3줄 → 0:20 1층 진입 → **0:30 적 없는 구역 + 표적 3개에서 스윗스팟 성공을 반드시 한 번** → 1:00 첫 추적형 → 1:30 첫 금기 재료
- 2단(첫 사이클 ~10분): 3:00 귀환·결과 → 3:30 첫 가공·판매 → **4:30 관계 첫 상승 + CG 갤러리 8칸(전부 잠김) 노출** → 5:00 두 번째 다이브 → ~10:00 첫 업그레이드

### 콘텐츠 팩 (단일 소스 = JSON, ScriptableObject 폐기)
- `StreamingAssets/content/` 아래: `pack.json` / `config/`(combat·erosion·economy·progression) / `entities/`(weapons·enemies·materials·recipes·upgrades·floors·droptables) / `narrative/`(story_events·cg·endings) / `locale/strings.csv` / `art/` / `audio/`
- 최상위는 `{ "schemaVersion": 1, "items": [...] }`. 모든 엔티티에 **소문자 스네이크·전역 유일 `id`**. 표시 텍스트는 `nameKey`/`descKey`로만. 참조는 전부 문자열 ID. 모르는 필드는 무시, 없는 필드는 기본값
- 무기·적은 `behavior`(코드 키) + `params`(자유 딕셔너리). behavior 클래스가 자기 `ParamSchema`를 스스로 신고하고 검증기가 그걸로 자동 검사
- 트리거 조건 9종: `affinity_at_least`/`affinity_below`/`cycle_at_least`/`floor_first_reached`/`recipe_unlocked`/`item_crafted`/`upgrade_at_least`/`flag_set`·`flag_not_set`/`gold_at_least`. **AND 배열만. OR도, 표현식 문자열도 없다** — OR이 필요하면 이벤트를 두 개 쓴다
- 효과 9종: `set_flag`/`clear_flag`/`add_affinity`/`unlock_recipe`/`unlock_cg`/`give_material`/`give_gold`/`unlock_floor`/`trigger_ending`
- 효과 키 6종: `backpack_slots`/`erosion_decay_rate`/`weapon_damage`/`weapon_scale`/`cauldron_slots`/`refinery_level`
- 스토리 판정은 **마을 복귀 시 1회**, 여럿이면 `priority` 내림차순 순차 재생
- ID 접두사: `wpn_`/`enm_`/`mat_`/`itm_`/`rcp_`/`upg_`/`drop_`/`floor_`/`evt_`/`cg_`/`end_`/`flag_`. **층 id에 번호를 쓰지 않는다**
- 최소 팩(`content_minimal/`)을 저장소에 커밋하고 CI에서 부팅시킨다 — 구조가 살아 있는지 확인하는 카나리아

### 세이브

## 테스트 결정

### 테스트 경계 — 무엇을 감쌀 것인가
**EditMode 단위 테스트만. PlayMode 테스트는 한 개도 만들지 않는다.**

경계는 **`Game.Domain`의 순수 로직**에 둔다. 특히 두 조정자를 통째로 감싸는 것이 이 프로젝트의 핵심 안전망이다.

| 대상 | 검증 |
|---|---|
| `ChargeLogic` | 릴리즈 시각 → 3구간 판정, 경계값, 자동발사 |
| `SwordWaveLogic` | 상태 전이, maxRange U턴, 귀환 추적, 타임아웃 |
| `ErosionLogic` | 시간·피격 감소, 정화 회복과 상한 100, 구간 판정, 0 도달 처리 |
| `BackpackLogic` | 용량 초과, 스택, 50% 상실 계산 |
| `PricingLogic` | 품질 계산, 직판 30%, 판매가 |
| `RecipeLogic` | 매칭, 재료 부족, 슬롯 점유 |
| `TriggerEvaluator` | 조건 9종 개별 평가, AND 결합 |
| **`DiveSession`** | **다이브 한 판 전체 시뮬레이션** (경계 조건이 전부 여기 있으므로) |
| **`CycleSession`** | **22사이클 경제 시뮬레이션** (순서를 소유하므로) |
| `SaveComposer` | 직렬화 왕복, 미지 ID 무시, 없는 필드 기본값 |

**결정론이 전제다** — Domain 내 `UnityEngine.Random`/`Time`/`DateTime.Now` 금지, seed 주입. 시간·입력은 `Tick(deltaTime, ...)`으로 주입받는다.

### 데이터는 테스트가 아니라 검증기가 지킨다
로직 = 테스트, 데이터 = `ContentValidator`. 섞지 않는다. 검증 10항목: JSON 문법 / id 중복 / **참조 무결성** / behavior·key·type이 레지스트리에 있는가(사용 가능한 키 목록 동봉) / `params`가 `ParamSchema`를 만족하는가 / 로케일 키 미정의·미사용 / 애셋 경로 실존 / 층 체인 순환 / 레시피 도달 가능성 / **엔딩이 전부 거짓일 수 있는가**.

**리포트는 반드시 전부 모아서 한 번에 출력한다** — 첫 에러에서 멈추면 콘텐츠 작업 속도가 죽는다. 에디터·개발 빌드는 부팅 중단 + 전체 리포트, 릴리스 빌드는 무시 + 로그.

### CI가 매 커밋 확인하는 것
- **빈 팩 부팅 테스트** — 크래시 없이 "콘텐츠 없음" 화면 + 리포트
- `content_minimal/` 팩 부팅
- 정규식 grep 2종(표시 문자열 / 튜닝 숫자 리터럴)이 0건
- `Game.Domain.asmdef`에서 UnityEngine 참조를 빼고 컴파일

### 테스트하지 않기로 한 것
- **MonoBehaviour, 씬, 렌더링, 입력, 이펙트, UI 배치, 애니메이션** — 비용 대비 회귀 방지 가치가 낮고 PlayMode 테스트는 느리고 깨지기 쉽다
- **손맛** — 테스트로 검증 불가. 그건 튜닝 패널 + 계측 로그 + 게이트 1의 몫이다. **테스트는 회귀 방지, 튜닝 패널은 감각 판정. 섞지 않는다**
- **밸런스 수치의 "옳음"** — 경제 시뮬레이터가 곡선을 출력할 뿐, 곡선이 좋은지는 사람이 판정한다
